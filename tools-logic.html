Getting started

Logic is built with one tool: Q menu > KGX's Admin Toolbox > World > Logic. You place nodes (buttons, trigger boxes, timers, counters and so on), then give each node outputs: "When this happens, do that". Everything is saved per map in data/kgx_admin_toolbox/logic_<map>.json and comes back after a restart. This guide covers v3.6.21.6.1, which adds event nodes and actions for every part of the toolbox: the economy, the police and the Mayor, staff, day and night, progression, the phone and more.

The node editor

The editor opens when you place a node, or when you right-click one. From top to bottom it has:

  1. The node's help, and its Name (shown in lists and pickers).
  2. Runs: off means the node is disabled until something sends it an Enable input.
  3. The node's settings. Hover any field for a tooltip.
  4. Body position and angle (buttons, switches, Button (multiple)): six sliders that move and turn the body live, plus Reset position, Flip and Turn 90 degrees. The new position is kept only when you click Save.
  5. Now: the node's live state, such as enabled or disabled, on or off, a counter's value, a timer running, or how many things are inside.
  6. The output list, with the columns When · Do · Target · Delay · Once. Double-click a row to edit it.
  7. Buttons: Add output, Edit, Duplicate output, Remove, a list of events and Test, Copy node, Save as preset…, Save and Delete node.

Test fires the chosen event right away, with you as the activator. It only runs outputs that are already saved, so click Save first. Nothing is stored until you click Save; closing the window throws the changes away.

Limits
  • Up to 400 nodes per map, and up to 32 outputs per node.
  • Each node gets an id: L1, L2, L3… Other nodes, conditions and talking NPCs use that id to point at it.
  • Players can't physgun node bodies. Only the Logic, Inspect and Remover tools work on them. A body removed some other way comes back in 2 seconds.

How logic works

Every piece of logic follows one sentence: when an event happens on a node, do an action, after a delay, if the conditions hold. A node sending an input to another node is just one of those actions, so you can chain nodes as far as you like.

Each output takes this path on its own. When the action sends an input to another node, that node's event starts the path again, one step deeper.

The parts
  • Node: a thing on the map with a kind (Button, Timer, Counter…), its settings and up to 32 outputs.
  • Event ("When"): something that happened to the node, such as OnPressed, OnEnter, OnTimer or OnHitMax. Each kind has its own list (see Node reference). Every kind also has OnEnabled, OnDisabled, OnVoteWin and OnVoteLose.
  • Output: one line in the editor: When, Do, Target, the action's fields, Delay, Only once and Only if. A node can have several outputs for the same event, and they all run.
  • Action ("Do"): what happens: open a door, show a message, teleport, send an input to another node, start a vote, and so on (see Actions).
  • Input: a command one node sends to another with the action Logic node: send an input (Press, Trigger, Add, SetA, Start, Open…). Some inputs take a value: Add 5, SetA on, Value 3.
  • Activator: whoever set the chain off. It is passed down the chain and kept through delays, so "the activator" in an action five nodes later is still the person who pressed the first button. {name} in texts becomes the activator's name, or "someone" when there is none.

Enabled and disabled

Most nodes take Enable and Disable inputs. Timer, Counter and Logic gate don't list them in the input picker: stop a timer with Stop, or untick Runs in the editor. A disabled node ignores every other input and fires nothing on its own. A disabled trigger also forgets who was inside.

Trigger boxes, spheres, relays and walls also take Toggle, which switches between enabled and disabled. For a switch, a branch or a timer, Toggle works on the node's own state instead.

Disabling a running Delay or Countdown cancels it, and it fires OnCanceled.

Delay, Only once and Random
  • Delay (0–3600 s): the action runs that many seconds later. If you edit and save the node before the delay ends, the waiting action is dropped.
  • Only once: the output runs the first time only, until the map restarts. Saving the node resets it.
  • A Random node runs one of the outputs that match its event, picked at random. Every other node runs all of them.
Safety limits
  • Chain depth: a chain stops after 24 steps (node → node → node…), so two nodes triggering each other can't freeze the server. The count goes on through delays and through the events an action sets off (an action that wants someone, which fires OnWanted again; one that sets the time or noclip, which fires OnNight or OnNoclipOn again…), so a loop with a delay in it stops too. For something that should repeat forever, use a Timer node: each tick starts a fresh chain.
  • Rate: at most kgxat_logic_rate actions per second on the whole server (default 400, range 50–5000). Above that, the rest are skipped and the server log says "a loop?".
  • Master switch: kgxat_logic 0 stops all logic from running. The nodes stay saved.
  • Map cleanup: a cleanup resets every node's live state: switches go back to their start, counters to their start value, timers to their "Runs from the start" setting. Map start nodes then fire OnCleanup. Variables are not reset by a cleanup.

Case (switch) Matches a value against up to 8 cases. Value (the value to check), Enable, Disable OnCase1–8, OnDefault (no match) Case 1–8 (a number or word; empty = unused). Defaults 1, 2, 3

  • Gate: the first time A or B is set, it fires OnTrue or OnFalse. After that it fires only when the result flips. Check fires the current result even if it hasn't changed. OnChanged fires only on a real flip.
  • Counter: values are kept between Lowest and Highest. Reaching Highest fires OnHitMax; with "Back to the start" it then jumps back to Starts at. Reset sets it to Starts at and also fires OnReset.
  • Compare checks by itself whenever its variable changes, and fires only when the result flips. Check always fires.
  • Case: numbers match as numbers (3 = 3.0), words match ignoring case. Feed it a vote's winner number, a counter's value or a word from a page.
  • Sequence: Next goes 1 → 2 → 3. After the last step it either loops (OnLoop, then OnStep1 again) or stops and fires OnEnd once, until Reset. Previous goes back one step and fires that step again; at step 1 it does nothing.

Only if: conditions on outputs

Any output can have up to three conditions. It runs only when they hold, so one button can do different things for different people. Conditions are checked against the activator at the moment the output fires, before its delay.

In the output editor:

  1. Only if sets the mode: ALL of them are true (AND) or ANY of them is true (OR).
  2. If 1, If 2, If 3: pick a condition. "(no condition)" leaves that row empty.
  3. value: what the condition checks against. Not every condition needs one.
  4. NOT: flips that one row, so "not an admin" or "does not hold a crowbar".

Actions (Do)

An output's Do button opens a searchable list of every action, grouped into 18 categories (v3.6.21.6.1: Economy, Menus & screens, Police & Mayor and World are new, and the Game modes action shows in the list again). The list only shows the actions you may use. Who in the tables below means whose nodes may run the action: Anyone (players with the tool too), Admins or Superadmins.

An admin action runs only while the node was last saved by a toolbox admin. If a player edits and saves their own node, the admin actions are dropped from it. The editor warns you under such actions.

Variables, votes and windows

Variables

Variables are named numbers shared by the whole server. Use them for scores, stages, how many keys were found, or whether the vault is open.

  • Set them with the admin action Change a variable (Set to, Add, Subtract).
  • Read them with a Compare node (fires OnTrue / OnFalse when the result flips), or the A variable condition (keys >= 3).
  • Show them on the HUD with the token {x:lv_name} in Settings > HUD, for example "Keys: {x:lv_keys}".
  • Names: letters, digits, _ and -, lower case, up to 32 characters. Anything else is stripped. A variable never set counts as 0.
  • Up to 64 variables per map. They last until the map changes or the server restarts; a cleanup doesn't reset them. Values run from −1,000,000,000 to 1,000,000,000, and decimals work.

Use a Counter instead when you only need a number inside one puzzle: it has limits, OnHitMax and Reset. Use a variable when several nodes, conditions or the HUD need to read it.

Votes

The Vote action (admins' nodes) starts a server vote. Every player sees the normal vote panel.

Vote What it asks Options field
Yes or no Your question. Passes when Yes reaches Yes needed % (with at least one Yes). Not used
A poll Your question, with your answers Answers, comma separated (up to 9)
The next map Which map next; the winner is loaded Maps, comma separated, or empty = the map pool
The server mode Sandbox, Build / PvP, RP…; the winner is switched to Not used
A Game Modes match Which mode to play; the winner's match starts Mode ids, comma separated, or empty = every mode (up to 9)
A job election Who becomes the Job name Not used. Candidates: the activator (a yes / no vote), everyone online, or everyone near the node (up to 9). The winner becomes the job if it isn't full.

Other fields: Question ({name} = the activator), Seconds (10–300, default 30), Yes needed % (yes / no votes and one-candidate elections).

Reacting to the result works in two ways. You can use both.

  1. On the node that started the vote: add outputs for OnVoteWin (passed, or has a winner) and OnVoteLose (failed, or nobody voted). The activator is the person who set off the vote. This is the easy way: When OnVoteWin, Do Teleport to a warp.
  2. A result node (optional target): pick a node. It gets Result node: input on yes / a winner (default Trigger), with the winning option's number as the value, or input on no / nobody (empty = none). Send the winner into a Case node (input Value) to branch on which option won: OnCase1 for option 1, OnCase2 for option 2, and so on.

If a vote can't start (another vote is running, or the job doesn't exist), OnVoteLose fires right away. Each node runs one vote at a time.

Windows: Button (multiple) and Custom page

Both show the same window: a title, a text (up to 1000 characters, multiple lines) and up to 8 buttons. A button with an empty label isn't shown.

  • Button (multiple) is a body players press with E. The window opens for whoever pressed. Its Open input opens it for the activator.
  • Custom page has no body. Its Open input opens it for its Opens for audience, and Close closes it for them. Open it from anything: a trigger box ("Welcome to the shop"), a timer, a chat word, a Map start, a vote.
Event When
OnOpened The window opened. Fires once per player it opened for; that player is the activator.
OnOption1 … OnOption8 That button was clicked. The activator is who clicked.
OnAnyOption Any button was clicked (fires along with OnOptionN)
OnClosed The player closed the window themselves
  • Each button asks "Are you sure?" first: a Yes / No box before the click counts.
  • The window closes after a button: off keeps it open, so players can click several buttons (a jukebox, a shop).
  • A click only counts from the window the server opened for that player, while they're alive and the node is enabled. For Button (multiple), they also have to stay within 250 units of the body.
  • Combine the buttons with Only if conditions to make a shop: Option 1 "Buy armor (500)" → Give armor only if they have at least 500, plus Player: Money −500 with the same condition.
Countdown on screen

A Countdown node shows big text with the time left ({time}) to its audience, in its color. Then it fires OnFinished, with whoever started it as the activator. Cancel or Disable removes it from screens and fires OnCanceled. A map cleanup clears every countdown.

Copy, presets, debugging and permissions

Copy and paste
  • Copy one node: E + right-click it, or click Copy node in its editor, or right-click it in the node list.
  • Paste: set Mode to Paste and left-click. The copy keeps the kind, name, settings, outputs and facing, and a box keeps its size. Outputs that pointed at other nodes still point at those same nodes.
  • Players (not admins) paste by the same rules as saving: outputs to doors, nodes, spawners or sound emitters that are not theirs are left out, an Entity watcher must watch something of theirs, and they cannot paste a Zone watcher. This holds for presets too.
  • Pasting an Entity watcher needs you to aim at the new entity to watch. A Zone watcher must be pasted inside a zone.
Group copy

A group copy keeps a whole build together, such as a door puzzle with its buttons, relay and counter. Make one in any of these ways:

  • Ctrl / Shift + click nodes in the node list, then Copy the selected nodes together (up to 64).
  • Copy every node within 256 units of me.
  • With the tool: Shift + E + right-click each node to add it (again to remove it).

When you paste a group, the nodes are placed around where you aim and keep their spacing. Outputs between the copied nodes are rewired to the new copies, so the pasted puzzle is a separate working puzzle, not a remote control for the old one.

Presets
  • Save as preset… in a node's editor saves the node as it was last saved, so click Save first.
  • Presets work on every map and anyone with the Logic tool can paste them. Up to 200, kept in data/kgx_admin_toolbox/logic_presets.json.
  • Saving under an existing name replaces it, if it's yours. Admins may replace or delete anyone's.
  • To use one, pick it in the panel's Presets list, click Paste the selected preset, then left-click. Paste the copied node instead switches back to your clipboard.
Debugging
  • With the Logic tool out, every node is drawn, with lines to everything its outputs drive.
  • Show nodes and fires without the tool (kgxat_logic_debug 1) keeps that view without the tool. It also shows a feed of the last 8 fires on screen ("Vault button: OnPressed (Kris)") and prints them to your console as [Logic]. Only players who may use the Logic tool get it.
  • The editor's Now: line shows the live state, and Test fires any event with you as the activator.
  • If a chain stops halfway, look at the server console for "more than 400 actions in one second" (a loop) or a "logic action …" error. Then check the Only if conditions, and whether a node is disabled.

  • Every node placed, edited, pasted or removed is written to the admin log.

Recipes

Each recipe is a full build. Bold words are what you pick in the editor. "Add output" means: in the node's editor, click Add output, set When, pick Do, pick the Target, then fill in the fields. Click Save on every node when you're done.

1. A button that opens a door for 5 seconds
  1. Place a Button next to the door. Set Cooldown to 6 so it can't be pressed while the door is open.
  2. Add output: When OnPressed → Do Door / mover / elevator → Target: the door → Do Open.
  3. Add output: When OnPressed → the same door → Close, Delay 5.
  4. Optional: When OnTooSoon → Show a message "Wait for the door" To The one who set it off.
2. A VIP-only door, with an answer for everyone else
  1. Place a Button. Add output: When OnPressed → door Open. Only if: If 1 = Their rank is, value vip, superadmin.
  2. Add output: When OnPressed → Show a message "VIP only" To the activator. Only if: the same condition with NOT ticked.

That is the pattern for if / else with any condition: job, license, weapon, health, money or a variable.

3. An elevator panel
  1. Make warp points with World > Warps: floor1, floor2, roof. An admin's node can use any warp. A player's own node can only use public warps.
  2. Place a Button (multiple). Set Window title "Elevator", Button 1 "Ground floor", Button 2 "Second floor", Button 3 "Roof", and HUD prompt "Elevator".
  3. Add outputs: When OnOption1 → Teleport to a warp floor1, Who the activator; OnOption2 → floor2; OnOption3 → roof.
  4. Optional: When OnAnyOption → Play a sound plats/elevbell1.wav At the activator.
4. Find the three hidden switches
  1. Place a Counter: Starts at 0, Lowest 0, Highest 3.
  2. Place three Buttons with Look Invisible behind paintings, each with HUD prompt "Something's here".
  3. On each button add output: When OnPressed → Logic node: send an input → the counter → Input Add. Tick Only once.
  4. On the counter add outputs: When OnHitMax → vault door Open, and When OnHitMax → Announcement "{name} opened the vault!" To Everyone.
  5. Nothing more is needed for a restart: a map cleanup resets the counter and the Only once marks by itself. For a reset without a cleanup, add an admin button that sends Reset to the counter.
5. Two players must stand on two plates
  1. Place two Pressure plates (A and B) and a Logic gate with Gate AND (both).
  2. Plate A: OnPressed → gate SetA, Value on; OnReleased → gate SetA, Value off. Do the same on plate B with SetB.
  3. Gate: When OnTrue → door Open; When OnFalse → door Close.
6. Vote to go to the arena
  1. Make a warp called arena. Place a Button with label "Vote: arena" and Cooldown 60.
  2. Add output: When OnPressed → Vote → Vote Yes or no, Question "{name} wants to go to the arena. Go?", Seconds 30, Yes needed 50. Leave the result node empty.
  3. Add output on the same button: When OnVoteWin → Teleport to a warp arena, Who Everyone.
  4. Add output: When OnVoteLose → Show a message "The vote failed" To Everyone near the node.
7. A poll that branches with Case
  1. Place a Case node with Case 1 = 1, Case 2 = 2, Case 3 = 3 (the defaults).
  2. On a button: When OnPressed → Vote → A poll, Options Arena, Race track, Hide and seek. Target: the Case node. Result input on a winner: Value.
  3. On the Case node: OnCase1 → teleport everyone to arena, OnCase2 → race, OnCase3 → Game mode Open a lobby for hideseek, OnDefault → a message "Nobody voted". The OnDefault only fires if you also set Result input on no / nobody to Value.
8. A round start with a countdown and a barrier
  1. Place an Invisible wall across the spawn exit, with Starts on.
  2. Place a Countdown (on screen): Seconds 10, Text "Round starts in {time}", Shown to Everyone, Color Red.
  3. Place a Switch for the admin, labelled "Start round". When OnOn → countdown Start.
  4. Countdown: When OnFinished → wall Disable; When OnFinished → Announcement "GO!"; When OnFinished → Play a sound For everyone.

9. A shop counter (Custom page)
  1. Place a Trigger box in front of the counter, Reacts to Players.
  2. Place a Custom page: Opens for The one who set it off, title "Gun shop", text "Pick an item", Button 1 "Pistol (200)", Button 2 "Armor (500)". Untick The window closes after a button.

Troubleshooting and tips

Problem Likely cause and fix
Nothing happens at all kgxat_logic is 0, or the node is disabled ("Now: disabled" in its editor; tick Runs). Turn on debug to see whether the event fires.
The event fires but the output doesn't run An Only if condition is false for that activator. Timers and clocks have no activator, so player conditions fail there. Or Only once already ran: save the node or clean up the map to reset it.
"Saved … (N output(s) left out)" Those outputs used an action you may not use, or aimed at something that isn't yours or no longer exists.
An admin action stopped working A player saved the node after you did. Admin actions run only while an admin saved the node last. Re-save it as an admin.
Test does nothing Test only runs saved outputs. Click Save, reopen, then Test.
A delayed output never ran The node was saved during the delay, which drops waiting actions.
A chain stops after a while The 24-step depth limit, or the rate limit (console: "more than 400 actions in one second"). Break loops with a Cooldown or Only once; for something that repeats forever, use a Timer node.
A trigger fires for the wrong people Check Reacts to and Only (team, job, rank or NPC tag). Remember OnEnter fires for every entity, while OnPlayerEnter is players only.
"Everyone" only reaches people nearby It's a player's own node, so Everyone becomes near the node. Have an admin save it.
A teleport does nothing The warp name is wrong, or it isn't public and the node isn't an admin's.
A button's sound doesn't change Silent is ticked, or the path isn't a game sound. Use .wav / .mp3 / .ogg files from the game, or a sound script name; links don't work for button sounds.
A Compare node never fires It fires only when the result flips, or on Check. Send Check from a Map start node to get the first result.
Two nodes need the same "if" Put the condition on a Branch: set it from one place, and send Test where you need it. Or use a variable and the variable condition.

Tips

  • Name every node. The pickers and the node list show names, and "Vault counter" is easier to find than "Counter".
  • Use a Relay as a hub. Point many sources at one relay and give the relay all the outputs. One place to edit, and you can disable the whole contraption with one Disable.
  • Delays make sequences. One event with five outputs at 0, 1, 2, 3 and 4 seconds is a scripted scene.
  • Invisible buttons and HUD prompts make any wall, painting or prop interactive without a visible button.
  • Group-copy finished builds and save the key node as a preset, so you can rebuild a puzzle on another map in seconds.
  • Watch it live: keep kgxat_logic_debug 1 on while you build, and turn it off for players.
